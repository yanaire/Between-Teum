# 틈틈 (TEUMTEUM, 가칭) — Claude Code 작업 가이드

> 사회적 가면을 쓰고 벗는 바쁜 직장인을 위해,
> 차 안의 짜투리 시간을 준비·회복·위로의 작은 성취로 바꾸는 앱

현대자동차그룹 **Pleos Connect** (Android Automotive 기반) 차량용 앱 개발 공모전 출품작이다.
팀은 디자이너 1명 (이 저장소의 주인)과 개발자 1명이다.

이 저장소에서 하는 일은 **하이파이 UI 프로토타입**을 만드는 것이다. 이 프로토타입은 세 가지로 쓰인다.

1. 기획서 시안 이미지
2. 시연 영상
3. 12월 PT 데모

개발자는 같은 화면 스펙과 토큰을 보고 AAOS (Kotlin / Jetpack Compose)로 옮긴다.

## 1. 절대 규칙

1. **정차 중에만 세션을 연다.** 기어 P와 차속 0일 때만 틈 세션을 연다. 시뮬레이터에서 기어가 P를 벗어나거나 `uxRestricted`가 켜지면 어떤 화면이든 즉시 `H-02` (주행 중 화면)로 바꾼다. 예외는 없다.
2. **주 버튼은 한 화면에 하나다.** 보조 버튼은 최대 둘이고 시각적 무게를 확실히 낮춘다. 모든 버튼은 음성으로도 누를 수 있으므로 음성 힌트를 작게 표시한다. 예: `"시작"이라고 말해도 돼요`
3. **Pleos 규격을 따른다.** 손으로 만지는 모든 컴포넌트는 Pleos 기본 앱과 같은 크기와 상태를 쓴다 (`04-DESIGN-SYSTEM.md` §6, `07-PLEOS-FOUNDATION.md` §8). 모든 값은 Connect-S 17인치 px (1px = 1dp)다.
   - 주 버튼은 Basic button Large (높이 100, 라디우스 32)다.
   - 보조 버튼은 Medium (80, 24)이다.
   - 가장 작은 터치 대상은 Small (64)이다.
   - 본문 최소는 body.s 26, 읽어야 하는 정보 최소는 label.s 20이다.
   - 주행 중 문장은 title.l 40 이상이다 (글자 높이 5mm).
   - 텍스트 대비는 4.5:1 이상이다.
   - 색은 Pleos 시맨틱 토큰을 쓰고, 헥스 값을 직접 쓰지 않는다.
4. **레이아웃은 두 가지를 모두 만든다.**
   - **Portrait 840 × 1184** (기본): 핵심을 여기서 완결한다.
   - **Landscape 1700 × 1184** (확장): 부가 정보를 더한다.
   - Pleos에서 Activity 기본 방향은 portrait이고, 앱은 두 방향 모두에 대응해야 한다 (`02-IA.md` §3).
5. **화면 ID를 지킨다.** 컴포넌트 이름, 파일 이름, 라우트에 화면 ID를 쓴다. 예: `screens/F1-03-Breath.tsx`, 라우트 `/s/F1-03`. ID는 임의로 새로 만들지 않는다.
6. **차가 하는 일은 반드시 눈에 보이게 한다.** 이 앱의 감동은 화면보다 **캐빈**에서 나온다. 그래서 다음 다섯 가지를 데모 셸의 Cabin 패널에 실시간으로 그린다.
   - 앰비언트 색과 밝기
   - 등받이 각도
   - 공조
   - 창문과 블라인드
   - 음성 자막
7. **가면은 얼굴로 그리지 않는다.** 가면은 빛의 색이다. 가면 이모지, 가면 일러스트, 캐릭터는 금지한다.
8. **카피는 짧은 해요체로 쓴다.**
   - 버튼 라벨은 누르면 일어나는 일을 그대로 말한다.
   - 같은 동작은 처음부터 끝까지 같은 이름을 쓴다. 예: `다녀오기`, `끝내기`, `들어가기`
   - 느낌표와 이모지는 쓰지 않는다.
9. **생성형 AI 티 나는 UI를 만들지 않는다.** 다음은 금지다.
   - 보라·파랑 그라데이션 배경
   - 무분별한 글래스모피즘
   - 똑같은 카드 3열 그리드
   - 아이콘 + 제목 + 설명 반복 블록
   - 의미 없는 01/02/03 번호
10. **시그니처는 '틈 라이트' 하나다.** 화면 가운데 세로로 빛이 새어 나오는 틈 하나에만 대담함을 쓰고, 나머지는 조용하게 둔다 (`04-DESIGN-SYSTEM.md` §2).

## 2. 기술 스택 (권장 기본값)

디자이너가 다른 스택을 원하면 따른다.

| 항목 | 선택 |
|---|---|
| 프레임워크 | Vite, React 18, TypeScript |
| 스타일 | `tokens/tokens.css`를 `src/styles/`로 복사해 import한다 (JSON을 고치면 다시 생성). 다크·라이트는 `[data-theme]`, 그날의 가면은 `[data-mask="calm|firm|warm|focus|flex"]`, 앰버·수면 빛은 `[data-light]`, 폼팩터는 `[data-ff="S14|L|W|WF"]`로 바꾼다. CSS Modules 또는 Tailwind v4 (`@theme`에 변수 연결) |
| 모션 | Framer Motion. `prefers-reduced-motion`을 반드시 존중한다 |
| 상태 | Zustand. `vehicleStore` (차량 상태), `dayStore` (하루 메모리), `sessionStore` (세션 진행) |
| 라우팅 | 화면 ID 기반의 단순 라우터 (`/s/:screenId`). 데모 셸의 화면 점프 메뉴로 아무 화면이나 바로 열 수 있게 한다 |
| 폰트 | Asta Sans (Pleos 시스템 UI 폰트, Google Fonts), Manrope (큰 숫자, Pleos 피처 폰트, Google Fonts), MaruBuri (편지·다짐 문장 전용, 네이버 OFL). MaruBuri를 쓸 수 없으면 Gowun Batang으로 대체한다 |
| 음성 | 프로토타입에서는 Web Speech API (TTS·STT)가 있으면 쓰고, 없으면 스크립트 자막으로 대체한다 |

### 폴더 구조 (제안)

```
src/
  app/            데모 셸 (화면 프레임 + Cabin 패널 + 시뮬레이터 + 화면 점프)
  screens/        화면 ID별 파일 (ON-01 … I-03)
  components/     MomentCard, SessionFrame, SeamLight, MaskCarousel, MicButton …
  cabin/          vehicleStore, cabinCommands (mock), cue 타임라인 엔진
  domain/         틈 감지 규칙, 시간 계산, dayStore, 문구 사전
  styles/         tokens.css, typography.css
```

## 3. 작업 순서

각 단계가 끝나면 스크린샷으로 확인한다. Portrait와 Landscape 두 크기에서 모두 본다.

1. **토대**
   - `tokens/tokens.css`를 가져와 전역으로 import한다.
   - 폰트 (Asta Sans, Manrope, MaruBuri)를 로드한다.
   - Pleos 기본 컴포넌트를 먼저 만든다: Basic button L·M·S, Toggle, Text button, Icon button, Tabs, Switch, Stepper, Spinner, System popup, Toast popup, Page navigation, 리스트 항목. 규격은 `07-PLEOS-FOUNDATION.md` §8을 따른다.
   - 데모 셸을 만든다 (`05-VEHICLE-MOCK.md` §1).
     - Connect-S 2560 × 1440 화면 전체를 축소해 보여 준다: 상태바, Driving view, GNB 목업, 앱 창.
     - 창 모드 (Portrait 840 × 1184, Landscape 1700 × 1184)와 폼팩터를 전환할 수 있게 한다.
     - Cabin 패널과 시뮬레이터 컨트롤을 둔다.
   - `SeamLight` 컴포넌트를 만든다.
2. **우선 시안 8개** (`02-IA.md` §6)
   - `H-01` 홈
   - `M-01` 모먼트 카드
   - `F1-03` 호흡
   - `F1-05` 오늘의 가면
   - `F2-04` 잠들기 전환
   - `F2-06` 기상 연출
   - `F4-03` 오늘 돌아보기
   - `F4-05` 이번 주의 나
3. **P0 나머지.** 공통 프레임 `C-01`~`C-04`, `T-01`과 F1·F2·F4 전체 흐름, `ON` 온보딩, `H-02`, `I-01`, `I-02`를 만든다. 시나리오 프리셋으로 아침부터 저녁까지 이어지는 '하루 루프'가 끊김 없이 돌아가야 한다.
4. **P1.** F3 리허설, Q1 3분 리셋, R 기록, ST 설정, `H-03`, `I-03`을 만든다.
5. **데모 모드.** 시간 빨리감기 (1분 = 5초)를 켜면 아침, 점심, 저녁 루프를 3분 안에 보여 줄 수 있어야 한다.

### 화면 하나의 완료 기준

- `03-FLOWS.md`의 요소, 카피, 분기가 모두 구현돼 있다.
- Portrait와 Landscape 레이아웃이 모두 동작한다.
- Pleos 컴포넌트 규격과 시맨틱 컬러 토큰만 썼다 (헥스 값 직접 사용 없음).
- 표에 적힌 '차의 동작'이 Cabin 패널에 보인다.
- 다음 화면으로 넘어가는 전이 애니메이션이 있다.
- 주행 신호를 주면 `H-02`로 바뀐다.
- 키보드 포커스가 보이고, reduced-motion이 켜져 있으면 모션이 꺼진다.

## 4. 용어

| 용어 | 뜻 |
|---|---|
| 틈 | 차가 정차해 있는 5~30분의 짜투리 시간. 하루 네 번 (출근 직후, 점심 직후, 중요한 순간 직전, 귀가 직전) |

| 엣지 라이트 | 세션 화면 아래 가장자리의 3px 빛 선. 남은 시간에 따라 줄어든다 |
| 복귀 시퀀스 (`C-03`) | 세션 전에 저장한 시트·조명·공조 값으로 차를 되돌리는 과정 |
| 스탬프 | 틈 하나를 마칠 때 쌓이는 작은 성취. 연속 기록과 주간 기록으로 보인다 |
| 하루 메모리 | 아침 다짐과 가면, 낮 리허설, 저녁 회고, '내일의 나에게'를 잇는 기록. 저녁에 남긴 말이 다음 날 아침 `F1-01`에서 재생된다 |

## 5. 아직 정해지지 않은 것 (개발자 확인 필요)

- 에뮬레이터에서 등받이 이동, 블라인드, 앰비언트 변화를 확인할 수 있는가
- 앰비언트 밝기를 1초에 몇 번까지 바꿀 수 있는가 (호흡과 동기화가 가능한가)
- STT가 말하는 도중에 중간 결과를 주는가, "어·음"까지 받아쓰는가
- 시동을 끈 뒤 앱이 언제까지 살아 있는가
- 에뮬레이터의 실제 앱 창 크기가 Pleos 가이드 값 (Connect-S Portrait 840 × 1184, Landscape 1700 × 1184)과 같은지
- Basic button 라벨 글자 크기 (가이드에 수치가 없어 body.l·body.m Strong으로 매핑해 둠)
