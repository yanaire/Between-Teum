# Pleos Connect SDK 개발

사용자가 “배터리 잔량 위젯 추가해줘”, “창문을 여는 버튼 만들어줘”처럼 말하면 필요한 SDK를 찾아 기존 앱에 구현한다. 기능 추천이나 설명만 요청했다면 읽고 답하며 코드를 바꾸지 않는다.

개발 지시를 자연어로 받는다는 이유로 앱에 STT·TTS·Gleo를 추가하지 않는다. 사용자가 앱의 음성 기능을 요청한 경우에만 음성 모듈을 선택한다.

## 필요한 자료만 읽기

이 스킬 디렉터리를 기준으로 상대 경로를 해석한다.

1. 먼저 `references/feature-map.md`에서 요청의 영역을 고른다.
2. 해당 `references/vehicle/<Domain>.json` 또는 `references/modules/<Module>.json`만 읽는다.
3. 구현 전에 `references/implementation.md`를 읽는다.
4. 공개 문서와 SDK 파일의 차이가 관련되면 `references/compatibility.md`를 읽는다.

전체 JSON을 매번 프롬프트에 넣지 않는다. 각 파일에는 확인 날짜, SDK 버전, 실제 메서드 이름, 조회·설정·구독·지원 확인 여부와 공식 출처가 있다.

## 작업 순서

### 1. 요청을 기능으로 분해

다음 네 가지를 정한다.

- 표시하거나 바꿀 대상: 배터리, 창문, 목적지, 음성 메모 등
- 동작: 조회, 변경 구독, 제어, 앱 내부 계산·저장, 외부 데이터 연동
- 영역: 운전석/동승석/좌우 창문 등
- 완료 조건: 사용자가 어느 화면에서 무엇을 확인할 수 있어야 하는가

프로젝트와 대화에서 알 수 있는 값은 다시 묻지 않는다. 영역이나 외부 데이터 공급자가 결과를 바꾸는데 알 수 없을 때만 질문한다.

### 2. 기존 프로젝트 확인

Gradle의 SDK 의존성·버전, Manifest, 화면 구조, 데이터 소유자, 생명주기와 기존 테스트를 읽는다. 기존 아키텍처를 따르고, 기능 하나 때문에 새로운 공통 프레임워크를 만들지 않는다.

이 프로젝트에서 확인한 조합은 Vehicle 2.3.2 / AGP 8.8.2 / Gradle 8.10.2 / Kotlin 2.0.0 / JDK 21이다. 다른 프로젝트나 변경된 버전에 이 조합을 강제로 적용하거나 의존성을 자동 업그레이드하지 않는다.

### 3. API 계약 확인

선택한 기능의 최신 공식 문서와 프로젝트에 실제로 설치된 SDK의 시그니처를 대조한다. 라이브러리 문서는 Context7 또는 공식 문서를 사용한다.

- 메서드가 있는지, 정확한 입력·반환·콜백 형식이 무엇인지 확인한다.
- 필요한 `@RequiresPermission`을 확인해 실제 사용하는 권한만 선언한다.
- 읽기와 제어 권한을 구분한다.
- 지원 여부, 영역, 허용 값 범위를 확인한다.
- 문서에 없는 이름을 비슷한 이름으로 만들어 내지 않는다.
- 콘솔에 있는 조작 기능을 SDK API라고 추정하지 않는다.

스냅샷은 2026-11-02 기준이다. 현재 버전이 다르면 관련 항목을 다시 확인한다. 새로 확인한 API는 버전·출처와 함께 갱신할 수 있다.

### 4. 구현

`references/implementation.md`에 따라 실제 SDK 호출, 실패 상태, 화면 갱신과 리소스 해제를 구현한다.

지원되지 않거나 권한이 없는 기능은 실제 상태를 표시한다. 임의 데이터, 빈 함수, 무조건 성공 응답으로 완성된 것처럼 보이게 하지 않는다.

### 5. 주행 상태 반영

주행 중 화면이나 조작 가능 여부는 플랫폼의 `CarUxRestrictions`로 판단한다. 속도가 0이라고 주차로 간주하지 않는다.

주행 규제를 강제로 끄거나 DO 선언만 추가해 제한을 우회하는 방식으로 해결하지 않는다. DO 앱도 현재 `ActiveRestrictions`에 맞춰 개별 기능을 제한한다.

### 6. 검증

- 프로젝트의 관련 테스트와 빌드·lint를 실행한다.
- 이 프로젝트의 기본 명령은 `./gradlew assembleDebug lintDebug`다.
- UI가 바뀌면 실제 에뮬레이터에서 조작하고 화면을 확인한다.
- 상태 표시라면 콘솔 값을 바꿔 UI 갱신을 확인한다.
- 제어라면 요청 완료와 실제 상태 반영을 구분해 확인한다.
- 주행 관련 기능은 P, D·정지, 이동, P 복귀를 구분한다.
- 구독 종료·화면 재진입과 미지원·오류 상태도 기능에 맞게 확인한다.
- 새 테스트는 저장소의 기존 테스트 위치와 방식에 맞춘다. 문서 문구를 고정하는 테스트는 만들지 않는다.

테스트 대상은 확인한 에뮬레이터로 지정한다. 연결된 기기가 여러 개이면 대상부터 확인하며 실제 차량을 임의로 조작하지 않는다.

### 7. 전달

구현한 동작, 바뀐 파일, 실행한 검증, 권한·외부 서비스 때문에 확인하지 못한 부분만 짧게 알린다. 새 기능이 실제로 동작하기 전에는 완료라고 하지 않는다.

## 자주 틀리는 선택

- 배터리 잔량 %: `EvBattery.getEvBatteryStateOfCharge`.
- 목표 온도 변경: `HVAC.setHvacTemperature`; 현재 실내 온도 조회와 구분.
- 현재 타이어 공기압: `getLowTirePressure`를 사용하지 않는다. 이 API는 저압 기준값이다.
- “근처 충전소”: `getChargerOperatorInfo`를 충전소 실시간 가용 목록으로 취급하지 않는다.
- Gleo `component="service"`: `sendBroadcast`와 `BroadcastReceiver`이며 `startService`가 아니다.
- STT 외부 PCM: `sendAudio` / `completeAudioSend`는 ON_DEVICE 경로다.
- 창문 50%: 콘솔 범위 0~100을 그대로 하드코딩하지 말고 차량의 해당 영역 허용 범위에 맞춘다.
